# Decisions

## 2026-05-07: MVP 部署基线采用 Docker + SQLite

决定：

- MVP 阶段继续使用 SQLite。
- 部署目标采用 Docker + SQLite。
- 数据目录集中在 `app/data`。

原因：

- 目标用户可能缺乏专业运维能力。
- SQLite 单文件更便于备份和迁移。
- 当前优先级是让业务闭环稳定可用，而不是提前扩展复杂基础设施。

影响：

- 所有新增功能必须兼容 SQLite。
- 需要做好备份、导出和迁移包。
- PostgreSQL 迁移作为后续专项，不混入当前 MVP。

## 2026-05-07: 不先重构成复杂 monorepo

决定：

- 继续保留现有 `app/` 结构。
- 不为了工程洁癖重构目录。

原因：

- 当前最大风险是构建、部署和业务闭环，不是目录形式。
- 单人/AI 协作更需要稳定、可理解、可验证的改动。

影响：

- 新代码优先放入现有 `app/src/backend/src/routes`、`app/src/pages`、`app/src/shared` 等路径。
- 如需拆分，必须有明确的复杂度收益。

## 2026-05-07: `src/backend/dist` 是生成物

决定：

- `app/src/backend/dist` 不作为开发入口。
- 后端源码只改 `app/src/backend/src`。

原因：

- 直接改 dist 会在下一次编译时丢失。
- dist 内容难以审查和维护。

影响：

- 修复后端问题时必须修改 TypeScript 源码。
- 验证使用 `npm run backend:build` 重新生成 dist。

## 2026-05-07: 总部聚合接口与分支接口分离

决定：

- 普通分支接口必须按 `tenantId` 隔离。
- 总部跨机构查看需要独立聚合接口。

原因：

- 多租户数据串读是高风险缺陷。
- 角色权限不能靠前端隐藏菜单保证。

影响：

- 新增查询必须先判断它是“本租户业务查询”还是“总部监管查询”。
- 总部统计可放在 `/api/dashboard/reports` 或后续 `/api/hq/*`。

## 2026-05-07: AI 运维先做规则化助手

决定：

- MVP 阶段不接入大模型。
- AI 运维页面先完成健康检查、备份、恢复、导出、日志等确定性能力。

原因：

- 运维功能的可靠性比自然语言体验更重要。
- 非专业运维人员首先需要可点击、可验证的按钮和结果。

影响：

- README 或页面文案不能夸大当前 AI 能力。
- 后续接入大模型前必须先有清晰的权限、安全和审计方案。

## 2026-05-07: 重要规则写入项目文档

决定：

- 项目方向、业务规则、权限矩阵、接口约定、验收清单和交接记录写入 `docs/`。

原因：

- 用户不希望项目随着聊天上下文压缩逐渐走偏。
- AI 每轮都能从项目文件恢复上下文。

影响：

- 每轮开发结束前必须更新 `docs/AI_HANDOFF.md`。
- 业务规则变化必须先更新相关 docs，再改代码。

## 2026-05-16: `xlsx` 依赖安全列为专项治理

决定：

- MVP 当前不直接替换 `xlsx`。
- 新增 `docs/DATA_SECURITY_BASELINE.md` 记录数据安全基线和依赖风险。
- 将 `xlsx` 高危公告列为后续依赖安全专项，先盘点使用点和测试覆盖，再评估替换或隔离方案。

原因：

- `xlsx` 覆盖报名表、成绩表、证书台账、档案数据等核心 Excel 导入导出路径。
- 2026-05-16 使用官方 npm registry 执行 `npm audit --omit=dev --registry=https://registry.npmjs.org --json`，显示 `xlsx` 为直接 high 风险且 `fixAvailable: false`。
- 盲目替换库或执行自动修复可能破坏本地官方模板兼容性和生产业务闭环。

影响：

- 上线前必须记录依赖审计结果。
- 所有 Excel 上传入口继续保持权限校验、文件大小限制、模板校验和错误兜底。
- 后续处理 `xlsx` 时必须同时覆盖报名、成绩、证书、档案导入导出回归。
