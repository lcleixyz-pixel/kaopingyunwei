# Role Matrix

## 角色定义

| 角色 | 枚举 | 说明 |
| --- | --- | --- |
| 系统管理员 | `SYS_ADMIN` | 系统初始化、配置、运维、全局管理 |
| 总部管理员 | `HQ_ADMIN` | 总部监管、审批、跨机构统计 |
| 总部工作人员 | `HQ_STAFF` | 总部查看和辅助处理 |
| 分支管理员 | `BRANCH_ADMIN` | 本分支计划、考生、节点、成绩、证书、档案管理 |
| 分支工作人员 | `BRANCH_STAFF` | 本分支日常考务处理 |
| 考评员 | `EXAMINER` | 后续用于考评执行和成绩相关流程 |
| 督导员 | `INSPECTOR` | 后续用于质量督导和抽查 |

## API 权限原则

- 所有业务写接口必须先经过 `authenticate`。
- 写接口必须显式调用 `requireRoles(...)`。
- 普通分支接口必须使用 `req.tenantId` 做数据过滤。
- 总部跨机构接口必须使用独立路径，例如 `/api/dashboard/reports` 或后续 `/api/hq/*`。
- 禁止在普通列表接口中用“如果是总部就不过滤租户”的方式混用数据边界。

## 当前可接受的角色开放策略

在 MVP 阶段，为了先完成闭环，可以允许：

- `SYS_ADMIN` 拥有全部能力。
- `HQ_ADMIN` 可进入成绩、证书、档案页面做监管。
- `BRANCH_ADMIN` 可管理本机构成绩、证书、档案。
- `BRANCH_STAFF` 可处理本机构考生和成绩基础录入。
- 意向考生为分支内部线索池，只允许 `BRANCH_ADMIN`、`BRANCH_STAFF` 使用；删除仅 `BRANCH_ADMIN`。
- 缴费状态是分支内部字段，只允许 `BRANCH_ADMIN` 和 `BRANCH_STAFF` 查看或修改；`SYS_ADMIN`、`HQ_ADMIN`、`HQ_STAFF` 均不可见。
- 总部角色可以通过 `/api/hq/*` 查看跨机构报名资料进度，但不得修改分支计划、节点、考生资料或缴费状态。

后续如果真实业务要求更细，需要在本文件先更新矩阵，再改代码。

## 权限验收样例

每次涉及权限变更，至少验证：

1. 系统管理员能登录并打开所有管理页面。
2. 分支管理员只能看到本机构计划和考生。
3. 分支工作人员不能打开系统设置。
4. 未登录请求业务 API 返回 401。
5. 角色不足请求写 API 返回 403。
6. 总部和系统管理员访问意向考生接口返回 403 或页面不可见。
7. 分支工作人员不能删除意向考生，分支管理员可以删除。
