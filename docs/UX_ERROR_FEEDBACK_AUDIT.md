# 友好提示与交互反馈检查记录

记录日期：2026-05-20

## 检查目标

本轮重点检查“用户输入不符合预期、点击高风险按钮、页面跳转、接口失败、上传下载失败”时，系统是否能给出明显、中文、可理解的提示。

## 已完成处理

- 统一前端提示框：新增 `PageAlert`，用于错误、成功、警告和普通信息提示。
- 统一高风险确认弹窗：新增 `useConfirmDialog`，替换业务页面中的浏览器原生确认框和取消计划备注输入框。
- 统一前端错误文案：新增 `getFriendlyErrorMessage` 和 `getFriendlyBlobErrorMessage`，页面不再直接读取原始后端错误结构。
- 无权限页面不再静默跳回首页，改为显示“没有权限访问该页面”的中文说明。
- 未登录访问受保护页面时，登录页显示“请先登录后再访问系统”。
- 仪表盘加载失败不再只写控制台，页面会展示“数据暂时加载失败，请刷新重试”。

## 静态护栏

已新增前端护栏测试，防止后续回退：

- 业务页面不再使用原生 `window.confirm` 或 `window.prompt`。
- 页面不再直接读取 `response.data.error` 原始错误。
- 无权限页面不再静默跳回首页。

## 剩余建议

- 后续如果新增页面，优先使用 `PageAlert` 和 `useConfirmDialog`。
- 后续如果引入更完整的 toast 系统，应保持“错误可见、可读、不中途消失太快”的原则。
- 后续可继续补浏览器自动化验收，覆盖真实点击后的弹窗和错误提示展示。
