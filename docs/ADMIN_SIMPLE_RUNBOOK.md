# 管理员傻瓜式运维手册

这份手册给不熟悉命令行的管理员使用。它只写最常用、最安全的操作。

## 先记住 4 个原则

- 生产环境不要随便删除文件。
- 任何升级、恢复、迁移前先备份。
- `.env`、数据库、上传文件、备份包、迁移包都不能公开。
- 不确定时先截图和保存日志，不要反复尝试危险操作。

## 日常健康检查

在浏览器里检查：

1. 打开系统地址。
2. 登录系统管理员账号。
3. 进入“AI 运维”。
4. 查看健康状态、数据库、磁盘和备份情况。
5. 如果页面提示异常，先记录截图。

在服务器命令行检查：

```bash
cd /root/exam-deploy
docker compose --env-file .env ps
curl http://127.0.0.1:8080/api/health
```

看到健康检查返回 `status: ok`，说明后端接口正常响应。

## 启动系统

```bash
cd /root/exam-deploy
./scripts/start.sh
```

启动后检查：

```bash
curl http://127.0.0.1:8080/api/health
docker compose --env-file .env ps
```

## 停止系统

```bash
cd /root/exam-deploy
./scripts/stop.sh
```

停止前请确认没有人在使用系统。

## 查看日志

```bash
cd /root/exam-deploy
docker compose --env-file .env logs --tail=120 backend
docker compose --env-file .env logs --tail=120 frontend
```

如果要发给技术人员，请先确认日志里没有密码、Token、Cookie 或备份包下载地址。

## 手动备份

优先在页面操作：

1. 登录系统管理员账号。
2. 进入“AI 运维”。
3. 点击备份。
4. 确认备份成功。

服务器上也可以复制数据库文件。复制前请先确认路径，以部署文档为准。

```bash
cd /root/exam-deploy
mkdir -p backup/manual
docker compose --env-file .env ps
```

不要把备份只放在服务器本机。至少复制一份到服务器外部的安全位置。

## 更新系统前检查

每次准备更新前，先确认：

- GitHub PR 已通过测试。
- 已经备份数据库。
- 已经通知使用者暂停操作。
- `.env` 仍然使用生产强密钥。
- `CORS_ORIGIN` 是真实 HTTPS 域名，不是 `*`。

## 更新系统

如果项目已经接入 GitHub Actions 自动部署，通常合并到 `main` 后会自动部署。

合并前请确认：

- 当前 PR 不是草稿状态。
- 测试已通过。
- 本轮改动不包含未确认的数据库破坏性变更。
- 有备份。

如果需要手动部署，以 `docs/DEPLOYMENT_CLOUD.md` 为准，不要临时拼命令。

## 恢复系统

恢复是高风险操作。除非已经确认当前数据不可用，否则不要直接恢复。

恢复前必须做：

1. 备份当前数据库，即使它可能有问题。
2. 记录当前时间、操作者和恢复原因。
3. 确认要恢复的备份文件来自可信来源。
4. 通知使用者暂停操作。

恢复后检查：

```bash
curl http://127.0.0.1:8080/api/health
```

然后登录系统，至少检查：

- 今日工作台能打开。
- 考评计划能读取。
- 报名资料能读取。
- 最近一条关键业务数据仍然存在。

## 账号和密码

新建账号：

1. 系统管理员登录。
2. 进入“系统设置”。
3. 打开“账号管理”。
4. 点击“新建账号”。
5. 选择机构和角色。
6. 设置临时密码。
7. 线下安全告知本人。

临时密码规则：

- 至少 12 位。
- 同时包含大写字母、小写字母、数字和特殊字符。
- 不能包含用户名。
- 不要通过微信群、公开文档或截图发送。

重置密码：

1. 找到账号。
2. 点击钥匙图标或重置密码按钮。
3. 设置新的临时密码。
4. 线下安全告知本人。

停用账号：

1. 找到账号。
2. 点击停用。
3. 不要删除历史账号。

## 用户反馈问题时怎么问

请让使用者提供：

- 发生时间。
- 使用账号姓名，不要提供密码。
- 操作页面。
- 点了哪个按钮。
- 页面提示截图。
- 是否能稳定复现。

不要让使用者把数据库、备份包或 `.env` 发到公开聊天中。

## 常见故障处理

| 现象 | 处理 |
| --- | --- |
| 页面打不开 | 检查宝塔/Nginx、域名 HTTPS、容器状态 |
| 登录失败 | 检查账号状态、密码、登录失败限流 |
| 提示无权限 | 检查账号角色和所属机构 |
| 上传失败 | 检查文件格式、大小和网络 |
| 导出失败 | 检查资料是否完整、证件照是否存在 |
| 健康检查失败 | 查看 backend 日志，先不要重启多次 |
| 磁盘空间不足 | 先备份，再清理旧镜像、旧日志或过期备份 |

## 什么时候必须找技术人员

- 数据库恢复。
- 生产 `.env` 泄露。
- 备份包或迁移包泄露。
- GitHub Actions 部署失败。
- 数据看起来串机构或权限异常。
- 页面出现英文错误堆栈。
- 需要改数据库表结构。
