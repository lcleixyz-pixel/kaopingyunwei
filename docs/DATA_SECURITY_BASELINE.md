# Data Security Baseline

本文记录 MVP 阶段的数据安全基线。它不是一次性安全审计报告，而是部署、验收和后续开发必须共同遵守的最低标准。

## 当前结论

- 仓库当前是 public，任何真实 `.env`、SQLite 数据库、上传文件、备份包、迁移包、证件照、证书附件和日志都不得提交、截图外传或公开分享。
- MVP 继续使用 Docker Compose + SQLite。SQLite 单文件便于备份和迁移，但也意味着数据库文件本身就是高敏资产。
- 认证密钥、加密密钥、初始化账号、CORS、HTTPS、备份恢复、迁移包下载和依赖漏洞是当前最需要持续盯住的安全面。

## 生产配置基线

- `JWT_SECRET` 和 `ENCRYPTION_KEY` 必须使用至少 32 字符的随机值，建议用 `openssl rand -base64 48` 生成。
- 生产环境禁止使用 `.env.example` 中的 `change-this-...` 占位值；后端已有启动校验，仍要在上线验收中人工确认。
- `CORS_ORIGIN` 生产环境必须设置为真实 HTTPS 域名，例如 `https://exam.example.com`，不能使用 `*`。
- 宝塔/Nginx 必须对公网启用 HTTPS；应用容器建议只绑定 `127.0.0.1:8080`，不要直接暴露公网 `80/443`。
- `.env` 只能留在服务器和受控备份中，不应进入 Git、聊天记录、邮件附件或公开文档。

## 账号与访问控制

- 初始化账号只用于首次初始化和验收，密码必须通过 `SEED_USER_PASSWORDS_JSON` 或受控密码管理器提供；生产上线后必须立即轮换 `admin`、`hqadmin`、分支管理员和工作人员密码。
- 登录接口已启用内存级失败限流：同一 `tenantCode + username + IP` 在 5 分钟内失败 5 次后，会被限制 15 分钟并返回 `LOGIN_RATE_LIMITED`。
- 导入、上传和 AI 运维高风险写入口已启用内存级限流：同一租户、用户、来源 IP 和路由键在 10 分钟内最多 20 次；超限返回 HTTP 429、错误码 `WRITE_RATE_LIMITED` 和中文提示。
- 每次涉及权限或页面入口调整，都要回归 `docs/ROLE_MATRIX.md` 和 `docs/ACCEPTANCE_CHECKLIST.md` 中的权限样例。
- 所有业务接口默认需要认证；新增写接口必须显式使用 `requireRoles(...)` 并记录审计日志。
- 普通分支接口必须按 `tenantId` 隔离；总部跨机构能力必须走独立聚合接口，不能混入分支列表接口。

## 结构化日志

- 后端已使用 Pino 输出 JSON 日志，默认生产 `info` 级别，可通过 `LOG_LEVEL` 调整。
- 请求日志记录方法、路径、状态码、耗时、用户、租户和来源 IP；不得写入明文密码、Token、Cookie、初始化密码 JSON 或证件敏感明文。
- Pino 日志已对 `password`、`token`、`authorization`、`cookie`、`SEED_USER_PASSWORDS_JSON`、`SMOKE_USER_PASSWORDS_JSON` 等字段脱敏。
- 路由层异常统一使用友好错误工具或结构化日志；禁止新增零散 `console.error`，也不要把 Zod 原始 `error.message` 直接返回给前端。
- 日志文件和容器日志可能包含业务路径、用户 ID、租户 ID 和错误上下文，安全等级不低于审计日志；生产导出、截图和外发前必须脱敏。

## 列表与输入保护

- 核心列表接口应优先支持 `page`/`pageSize`，并限制最大 `pageSize`；前端没有分页 UI 的接口必须保留无分页安全上限，避免一次性读取过多数据。
- 无分页列表超过安全上限时，应返回中文 `LIST_TOO_LARGE`，提示用户输入筛选条件或分页查看，不要静默截断数据。
- 写接口中的状态、备注、数量、ID 等关键输入必须先经过 Zod schema，再进入业务逻辑；不要直接读取 `req.body.status`、`req.body.notes` 等高风险字段。
- 新增路由建议优先使用 `parseBody` / `parseQuery` 封装 Zod 校验，保持中文 `VALIDATION_ERROR` 格式一致。

## 数据与备份

- 生产数据包括 Docker volumes 中的 SQLite 数据库、上传文件、备份目录和迁移包，不等同于宿主机项目目录下的 `app/data`。
- 备份至少保留两层：应用内备份或迁移包，以及服务器外部位置，例如对象存储、另一台机器或受控离线介质。
- 外部备份建议加密保存，并设置最小授权访问；迁移包下载完成后应及时删除或按保留策略清理。
- 恢复演练不能只验证文件存在，必须至少验证容器启动、`/api/health`、登录、核心页面和一条业务数据可读。
- 审计日志是业务追责依据，备份和迁移时必须保留；恢复后要抽查审计记录是否仍可读取。

## 文件与迁移包

- 上传文件和证件照应继续通过鉴权接口访问，不应直接暴露文件系统目录。
- 迁移包包含数据库和上传文件，敏感等级等同于全量生产数据；只允许系统管理员生成和下载。
- 迁移包链接和文件名不要发到公开渠道；如果需要临时传输，应使用受控网盘、对象存储临时凭证或内网传输。
- 下载、导出、备份、恢复等运维动作必须写入审计日志。
- AI 运维恢复和下载接口只接受受控文件名，不接受路径；恢复仅允许 `.db` 备份，下载仅允许 `.db` 或 `.tar.gz`。
- AI 运维日志查询必须限制行数，避免一次性返回过多审计数据；当前限制为 1-500 行。
- AI 运维备份、恢复和迁移导出接口已纳入高风险写操作限流；触发 429 时应等待 `Retry-After` 后再重试。

## 依赖安全

2026-05-16 使用官方 npm registry 执行生产依赖审计：

```bash
npm audit --omit=dev --registry=https://registry.npmjs.org --json
```

结果：

- `xlsx`：high，直接依赖，涉及 SheetJS prototype pollution 和 ReDoS 公告；当前 npm audit 显示 `fixAvailable: false`。
- `lodash`：high，间接依赖，涉及 prototype pollution 和 template code injection 公告；当前 npm audit 显示 `fixAvailable: true`。

处理策略：

- 本轮不直接替换 `xlsx`，因为 Excel 导入导出覆盖报名、成绩、证书、档案等核心业务路径，盲目替换容易造成生产回归。
- 后续应建立依赖安全专项，先盘点所有 `xlsx` 使用点，再评估替代库、版本来源、输入限制、模板白名单和解析隔离。
- 在专项完成前，所有 Excel 上传入口必须保持文件大小限制、业务模板校验、权限校验和错误兜底。
- 每次上线前至少运行一次官方 registry 的 `npm audit --omit=dev`，不要只依赖镜像源，因为部分镜像源不支持 audit endpoint。

## 近期优化方向

- 评估是否需要把登录失败限流从内存级升级为数据库或 Redis 持久化策略，以支持多副本部署和服务重启后保留失败计数。
- 评估是否需要把导入、上传和 AI 运维写操作限流从内存级升级为 Redis 或网关级策略，以支持多副本部署。
- 将备份包和迁移包的保留、下载、删除策略产品化，避免长期堆积全量敏感数据。
- 评估将生产外部备份加密和异地保存纳入标准部署步骤。
- 对 Excel 解析链路做专项治理，尤其是 `xlsx` 替换或隔离方案。
