# Acceptance Checklist

## 每轮开发前

- 读 `docs/AI_HANDOFF.md`，确认上一轮状态。
- 读本轮涉及的业务规则和角色矩阵。
- 明确本轮只做一个可验收目标。
- 检查是否会影响租户隔离、权限或审计日志。

## 基础命令验收

在 `app/` 目录执行：

```bash
npm run check
```

通过标准：

- 前端 TypeScript 编译通过。
- Vite 构建通过。
- Prisma Client 生成通过。
- 后端 TypeScript 编译通过。

继续执行：

```bash
npm run lint
```

通过标准：

- ESLint 无错误。

继续执行：

```bash
npx prisma migrate status --schema src/backend/prisma/schema.prisma
```

通过标准：

- 数据库 schema 与 migration 状态一致。

## 编译后运行验收

在 `app/` 目录执行：

```bash
npm run backend:start
```

通过标准：

- 服务在 `http://localhost:3001` 启动。
- `GET /api/health` 返回正常。
- 浏览器可打开登录页。

## 浏览器核心页面验收

使用系统管理员账号登录后，至少打开；密码从 `SEED_USER_PASSWORDS_JSON` 或受控密码管理器获取：

- 仪表盘
- 意向考生使用分支账号验证，系统管理员和总部账号不可见
- 考评计划
- 节点追踪
- 考生管理
- 成绩管理
- 证书管理
- 档案管理
- AI 运维
- 系统设置

通过标准：

- 页面没有白屏。
- 路由不跳错。
- 真实接口返回数据或空状态。
- 侧边栏提醒数量来自接口。
- AI 运维健康状态显示真实数据库、磁盘或备份信息。
- AI 运维下载、恢复、日志查询对非法文件名或过大行数返回中文友好错误。

## 分页验收

目标：核心列表不再一次性读取过多数据，避免大表慢加载或触发安全上限。

至少验证：

- 考评计划列表显示中文分页信息，点击“下一页/上一页”能切换页面。
- 报名资料工作台选择已发布计划后，考生列表按页加载；切换计划或搜索姓名后自动回到第 1 页。
- 意向考生列表按页加载；切换状态或搜索姓名/手机号后自动回到第 1 页。
- 系统设置中的账号管理按页加载；筛选机构、角色、状态或关键字后自动回到第 1 页。
- 当总数不超过一页时，不显示多余分页按钮。
- 分页请求携带 `page` 和 `pageSize`，接口响应包含 `meta.pagination`。

## Phase 1 核心闭环验收

目标：计划、节点、考生、提醒能形成业务闭环。

验收步骤：

1. 管理员登录。
2. 创建一个考评计划。
3. 系统自动生成 9 个节点。
4. 分支新增考生。
5. 审核考生通过或驳回。
6. 完成一个节点。
7. 检查仪表盘统计变化。
8. 检查提醒数量可见。
9. 检查审计日志出现对应记录。
10. 发布计划后确认“制定计划”节点自动完成，“考试报名”节点进入进行中。
11. 在报名资料工作台上传回填时选择确认结束报名，确认“考试报名”节点完成，后续新增正式考生和意向转正式均被阻断。
12. 节点追踪页面确认只展示已发布且未完成认定的计划，并按考试日期由近到远排序。

## 意向考生验收

目标：分支可以维护不绑定计划的意向考生，并在合适时转入正式考务闭环。

验收步骤：

1. 使用分支管理员账号登录，密码从 `SEED_USER_PASSWORDS_JSON` 或受控密码管理器获取。
2. 确认侧边栏顺序为“仪表盘 -> 意向考生 -> 考评计划”。
3. 确认进入页面默认选中“跟进中”，不是“全部”。
4. 新增意向考生，姓名和手机号必填。
5. 使用相同手机号再新增一条，确认前端提示重复但允许保存。
6. 使用分支工作人员账号验证可新增、编辑、转正式，但不能删除。
7. 使用总部或系统管理员账号验证页面不可见，接口返回 403。
8. 选择本分支已发布计划并补身份证号、性别等最小字段，转为正式考生。
9. 进入报名资料工作台，确认默认不会加载全部考生，必须先选择已发布计划。
10. 确认报名资料工作台计划下拉只显示已发布计划，不显示草稿和已取消计划。
11. 审核驳回该正式考生，确认对应意向考生恢复为“跟进中”，并且该正式考生不再出现在报名资料工作台。
12. 再转正式一名意向考生后回退计划到草稿，确认该计划内正式考生被移除，已转正式的意向考生恢复为“跟进中”。
13. 确认草稿计划不能转入意向考生，也不能直接新增正式考生。
14. 确认已发布计划不能直接取消；回退为无考生草稿后，填写取消备注才能取消。
15. 确认报名阶段结束后的已发布计划不能再被选为转正式目标。

## 字典规则验收

目标：等级、工种和报名资料固定选项不再自由漂移。

验收步骤：

1. 新建考评计划时，等级选项显示完整表述，如“三级/高级工”。
2. 职业为“贵金属首饰与宝玉石检测员”且等级为“五级/初级工”时，职业工种名称仅有“贵金属首饰与宝玉石检测员”。
3. 职业为“贵金属首饰与宝玉石检测员”且等级为一级至四级时，职业工种名称不再出现“贵金属首饰与宝玉石检测员”。
4. 意向考生和报名资料工作台中，等级均使用完整表述。
5. 报名资料工作台中文化程度、所在省（市）区、考生来源、报名单位、认定分类、考试类型均为固定选项。
6. 留空参加工作时间、电子邮箱、户籍所在地、政治面貌、学历证书编号、简要经历、通讯地址、邮政编码、邮寄地址时，审核通过不应被这些字段阻断。
7. 审核通过后的考生资料再次编辑保存时，前端应提示确认本地业务系统信息同步一致。

## Phase 2 业务闭环验收

目标：成绩、证书、档案能串成完整流程。

验收步骤：

1. 为已审核考生录入理论和实操成绩。
2. 系统计算总分和是否合格。
3. 复核成绩。
4. 为合格考生生成证书。
5. 将证书状态更新为已打印、已发放。
6. 对计划生成封存档案。
7. 检查档案哈希和文件大小。
8. 检查所有写操作审计日志。

## 多租户验收

至少验证：

- 北京分部不能读取上海分部计划。
- 北京分部不能修改上海分部考生。
- 总部跨机构统计使用专门接口。
- 普通分支接口不返回其他租户数据。

## 权限验收

至少验证：

- 未登录访问业务接口返回 401。
- 角色不足访问管理接口返回 403。
- 分支工作人员看不到系统设置入口，或打开后被拒绝。
- 系统管理员可执行 AI 运维操作。

## 数据安全验收

至少验证：

- `.env` 已使用生产随机 `JWT_SECRET` 和 `ENCRYPTION_KEY`，且没有使用 `.env.example` 占位值。
- 生产 `CORS_ORIGIN` 设置为真实 HTTPS 域名，不能使用 `*`。
- 初始化账号密码已轮换，至少覆盖 `admin`、`hqadmin`、分支管理员和工作人员。
- 登录失败限流有效：同一账号、租户和来源 IP 连续失败达到阈值后，`/api/auth/login` 返回 429、错误码 `LOGIN_RATE_LIMITED`，并带 `Retry-After` 响应头。
- 导入、上传和 AI 运维高风险写入口限流有效：连续触发同一入口达到阈值后返回 429、错误码 `WRITE_RATE_LIMITED`、中文提示和 `Retry-After` 响应头。
- 后端日志为 Pino JSON 格式，启动日志、请求日志和后台任务日志可按字段检索；抽查日志不得出现明文密码、Token、Cookie 或初始化密码 JSON。
- 后端路由护栏测试通过：路由文件不使用零散 `console.error`，不直接返回 Zod 原始 `error.message`。
- 核心列表接口有大数据保护：不分页读取超出安全上限时返回中文 `LIST_TOO_LARGE`，分页参数非法时返回中文 `VALIDATION_ERROR`。
- `.env`、SQLite 数据库、上传文件、备份包、迁移包没有进入 Git；当前仓库是 public 时尤其要确认。
- AI 运维可生成备份，且至少一份备份已复制到服务器外部位置。
- 至少抽测一次恢复流程或恢复预案：确认目标 volume、启动容器、访问 `/api/health`、登录并读取一条核心业务数据。
- 运维导出、备份、恢复、下载等动作在审计日志中可追踪。
- 运行官方 registry 依赖审计：

```bash
npm audit --omit=dev --registry=https://registry.npmjs.org
```

通过标准：

- 审计结果已记录在 `docs/AI_HANDOFF.md` 或发布记录中。
- 已知 `xlsx` 高危公告不盲目修复，按 `docs/DATA_SECURITY_BASELINE.md` 作为依赖安全专项处理。
- 可自动修复的间接依赖风险需要单独评估影响后再升级，不能无测试直接 `npm audit fix`。

## Docker 验收

如果机器具备 Docker：

```bash
docker compose --env-file .env -f docker/docker-compose.yml config
docker compose --env-file .env -f docker/docker-compose.yml up -d --build
curl http://127.0.0.1:${EXAM_PORT:-80}/api/health
```

通过标准：

- Compose 配置有效。
- 后端容器启动并完成 seed。
- 前端可访问。
- 初始化账号可登录，且密码来自 `SEED_USER_PASSWORDS_JSON` 或受控密码管理器。
- 如果云服务器已有宝塔或其他网站，确认 `.env` 中 `EXAM_PORT` 未占用公网 `80/443`，推荐使用 `127.0.0.1:8080` 并通过宝塔反向代理。

如果当前机器没有 `docker` 命令，必须在交接文档中明确记录未验收原因。

## 每轮结束

- 停止本地服务，释放端口。
- 更新 `docs/AI_HANDOFF.md`。
- 告诉用户：
  - 完成了什么
  - 验证了什么
  - 没有验证什么
  - 下一步建议
