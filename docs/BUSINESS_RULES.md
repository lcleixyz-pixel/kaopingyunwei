# Business Rules

## 总体规则

- 系统按租户隔离数据。普通分支用户只能访问本机构数据。
- 系统管理员和总部角色需要跨机构查看时，应使用明确的总部聚合接口。
- 所有敏感写操作必须记录审计日志。
- MVP 阶段以 SQLite 为准，不提前迁移 PostgreSQL。
- 页面功能必须反映真实接口，不使用固定假数据冒充业务状态。

## 考评计划

计划字段至少包括：

- 标题
- 职业
- 职业工种名称
- 等级
- 考试日期
- 报名截止日期
- 考试地点
- 最大考生数
- 状态
- 备注
- 创建人
- 创建时间

计划状态：

| 状态 | 含义 |
| --- | --- |
| `DRAFT` | 草稿 |
| `PENDING` | 待审批 |
| `APPROVED` | 已审批 |
| `REJECTED` | 已驳回 |
| `PUBLISHED` | 已发布 |
| `CANCELLED` | 已取消 |

规则：

- 创建计划后必须自动生成 9 个考评节点。
- 计划创建、发布、回退、取消必须写审计日志。
- 分支计划列表默认只展示本租户计划。
- 考评计划页面默认选中“已发布”，筛选顺序为“已发布、草稿、全部、已取消”。
- 总部统计不能复用分支列表接口做跨租户混查。
- 当前阶段不再使用“认定方式/考试类型：理论、实操、综合”作为计划字段。
- `profession` 在现有代码中语义为“职业工种名称”；`occupation` 表示“职业”。
- 等级统一使用完整表述：`一级/高级技师`、`二级/技师`、`三级/高级工`、`四级/中级工`、`五级/初级工`。意向等级、认定等级、证书等级均不得只存 `1`、`2`、`3`、`4`、`5`。
- 当前职业、等级和工种规则先固化为：
  - 职业“贵金属首饰与宝玉石检测员”：五级/初级工时仅可选工种“贵金属首饰与宝玉石检测员”。
  - 职业“贵金属首饰与宝玉石检测员”：一级至四级时可选工种“贵金属首饰检验员、钻石检验员、宝石检验员、玉石检验员、有机宝石检验员”，不可再选“贵金属首饰与宝玉石检测员”。
  - 职业“首饰设计师”：工种“首饰设计师”。
- 发布后锁定职业、职业工种名称、等级、考试日期、报名截止日期、考试地点、最大考生数等核心字段；备注类低风险信息可继续维护。
- 草稿状态可以编辑、发布或取消，但不能转入意向考生，也不能直接新增正式考生。
- 已发布状态可以转入意向考生，也可以直接新增正式考生；不能直接取消，只能先回退到草稿。
- 已发布计划的“考试报名”节点完成后，视为报名阶段结束，不能继续直接新增正式考生，也不能继续从意向考生转入正式考生。
- 已发布计划回退到草稿时，该计划内所有正式考生转为意向考生“跟进中”，并删除原正式考生记录。
- 取消计划前必须自检该计划下无正式考生，且必须填写取消备注；只有草稿计划可以取消。
- 已取消计划按规则不应再绑定正式考生，因此报名资料工作台不展示已取消计划。

## 意向考生

意向考生字段至少包括：

- 租户
- 姓名
- 手机号
- 意向职业
- 意向工种
- 意向等级
- 来源
- 跟进状态
- 备注
- 转正式后的正式考生 ID
- 创建时间
- 更新时间

跟进状态：

| 状态 | 含义 |
| --- | --- |
| `NEW` | 新线索 |
| `CONTACTED` | 已联系 |
| `INTERESTED` | 有意向 |
| `CONVERTED` | 已转正式 |
| `DROPPED` | 已放弃 |

规则：

- 意向考生只服务分支内部，不进入总部统计、报名导出、成绩、证书、档案。
- 只有 `BRANCH_ADMIN` 和 `BRANCH_STAFF` 可见和新增、编辑意向考生。
- 只有 `BRANCH_ADMIN` 可彻底删除意向考生。
- `SYS_ADMIN`、`HQ_ADMIN`、`HQ_STAFF` 无页面和接口访问权。
- 姓名和手机号必填。
- 同一分支内手机号重复时前端提醒，但允许保存。
- 转正式只能选择本分支已发布计划，并要求补充正式考生最小必填信息。
- 已发布计划如果已经完成“考试报名”节点，则不能再转入意向考生。
- 转正式后，正式考生自动带入计划的职业、职业工种名称、等级和报名单位等字段，再到报名资料工作台继续补齐 33 项模板资料。
- 意向考生页面默认展示“跟进中”，不默认展示“全部”。
- 已转正式的意向考生，如果其关联考评计划被回退到草稿，应恢复为“跟进中”并解除正式考生关联；该计划下正式考生记录不保留。
- 已转正式的意向考生，如果正式考生审核被驳回，应恢复为“跟进中”并解除正式考生关联；正式考生记录应移除，不在报名资料工作台重复显示。

## 考评节点

节点状态：

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 待处理 |
| `IN_PROGRESS` | 进行中 |
| `COMPLETED` | 已完成 |
| `OVERDUE` | 已逾期 |
| `SKIPPED` | 已跳过 |

规则：

- 节点根据计划考试日期计算截止日期。
- 节点追踪模块按考试计划管理，只展示已发布且尚未达到“完成认定”状态的计划，并按考试日期由近到远排序。
- 发布考试计划时，系统自动将该计划的“制定计划”节点登记为已完成，并将“考试报名”节点置为进行中。
- 完成节点必须记录完成人、完成时间和审计日志。
- 通过地方系统上传回填确认结束报名阶段时，系统自动将“考试报名”节点登记为已完成，并激活下一个待执行节点。
- 定时任务可将逾期节点标记为 `OVERDUE` 并生成提醒。
- 前端侧边栏和仪表盘提醒数量必须来自 `/api/reminders/count`。

## 考生

考生状态：

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 待审核 |
| `APPROVED` | 审核通过 |
| `REJECTED` | 审核驳回 |
| `EXAMINED` | 已考试 |
| `PASSED` | 成绩合格 |
| `FAILED` | 成绩不合格 |

规则：

- 身份证号必须加密存储，列表展示时必须脱敏。
- 新增、审核、驳回考生必须写审计日志。
- 考生必须绑定计划和租户。
- 分支不能读取或修改其他分支考生。
- Phase 1.1 起，考生报名资料必须对齐项目内 `/模版/考生信息模板.xls` 的 33 列字段。
- 当地上传导出只保留原模板表头和考生数据行，保持 `.xls` 格式，不追加系统内部字段。
- 系统内部固定材料清单为：身份证、证件照、学历证明、工作年限证明、申报表/承诺书、原职业资格/等级证书。
- 只有模板必填项补全、所需材料齐全且审核通过的考生可进入导出。
- 当“是否有职业资格证书”为“是”时，原职业资格/等级证书材料、证书等级和证书编号才作为闸门条件；无证书或初次认定不阻断。
- 缴费状态仅有“未缴/已缴”，只对 `BRANCH_ADMIN` 和 `BRANCH_STAFF` 可见可改；总部和系统管理员 API/页面均不可见。
- 文化程度固定选项为：博士、研究生、大学本科、大学专科和专科学校、中等专业学校、技校、高级技校、技师学院、高中、职高、初中、小学。
- 所在省（市）区按现行 34 个省级行政区设置选项：北京市、天津市、河北省、山西省、内蒙古自治区、辽宁省、吉林省、黑龙江省、上海市、江苏省、浙江省、安徽省、福建省、江西省、山东省、河南省、湖北省、湖南省、广东省、广西壮族自治区、海南省、重庆市、四川省、贵州省、云南省、西藏自治区、陕西省、甘肃省、青海省、宁夏回族自治区、新疆维吾尔自治区、台湾省、香港特别行政区、澳门特别行政区。
- 考生来源固定选项为：国有企业、集体企业、私营企业、个体企业、外商投资、港澳台商投资、职业高中、普通技工学校、高级技工学校、技师学院、职业技术学院、普通中专、普通高中、普通大专、普通大学、研究生院、其它、下岗失业人员、现役军人、农民工、劳改劳教人员、其他人员、机关事业单位。
- 报名单位固定选项为：国家珠宝玉石首饰检验集团有限公司、国检教育科技（深圳）有限公司、新疆中和鉴珠宝玉石质量检测研究所（有限公司）、宝检教育科技（云南）有限公司。
- 认定分类固定选项为：初次认定、晋级认定。
- 考试类型固定选项为：正考、补考。
- 参加工作时间、电子邮箱、户籍所在地、政治面貌、学历证书编号、简要经历、通讯地址、邮政编码、邮寄地址均为非必填项，不影响审核通过。
- 报名资料工作台默认必须先选择一个已发布考评计划，不加载全部计划下的全部考生。
- 报名资料工作台的计划下拉只展示已发布计划，不展示草稿和已取消计划。
- 已审核通过考生的报名资料如需再次编辑，前端必须提醒使用者先确认本地上级部门业务系统中的信息同步保持一致。
- 审核驳回正式考生时：
  - 如果该考生来自意向考生转正式，则原意向考生恢复为“跟进中”，并解除正式考生关联。
  - 如果该考生是直接新增的正式考生，则系统生成或复用同姓名、手机号的意向考生并置为“跟进中”。
  - 原正式考生记录删除，避免在报名资料工作台和意向考生中重复出现。

## 地方系统上传回填

规则：

- 分支导出并上传当地上级部门业务系统后，可以在计划级记录上传状态、上传时间、操作人和备注。
- 点选上传回填时，前端必须询问是否确认结束考试报名阶段；确认后完成“考试报名”节点并关闭继续新增/转入考生的入口，未确认则只记录上传状态且仍可继续新增/转入。
- 第一版只记录计划级上传批次，不记录单个考生的上传回执。
- 总部报表展示计划、节点、考生、材料齐全、审核通过、可导出和上传状态，不包含缴费字段。

## 成绩

成绩字段至少包括：

- 考生
- 理论成绩
- 实操成绩
- 总成绩
- 是否合格
- 录入人
- 复核人
- 录入时间
- 复核时间

规则：

- 成绩围绕 `Score` 表实现。
- 保存成绩时，如未提供总成绩，可按已有分项平均计算。
- 当前 MVP 默认通过线为总分大于等于 60。
- 成绩合格后考生状态更新为 `PASSED`，不合格更新为 `FAILED`。
- 成绩录入、修改、复核必须写审计日志。

## 证书

证书状态：

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 待制证 |
| `PRINTED` | 已打印 |
| `ISSUED` | 已发放 |
| `REISSUE_REQUESTED` | 补办申请中 |

规则：

- 只有成绩合格的考生可生成证书。
- 证书编号必须唯一。
- 证书生成、打印、发放、补办申请必须写审计日志。
- 证书页面不得只保留占位页，必须有表格、筛选和操作入口。

## 档案

档案状态：

| 状态 | 含义 |
| --- | --- |
| `SEALED` | 已封存 |
| `OPENED` | 已调阅 |

规则：

- 档案围绕 `Archive` 表实现。
- 封存档案时必须生成文件、文件大小和封存哈希。
- 调阅或状态变更必须写审计日志。
- 档案文件应存储在 `app/data/files` 下，不写入源码目录。

## AI 运维

规则：

- 健康检查必须读取真实环境信息，包括数据库连接、数据库大小、磁盘和备份状态。
- 备份文件存储在 `app/data/backups`。
- 导出迁移包必须包含数据库、上传文件、元数据和恢复说明。
- 备份、恢复、导出、下载迁移包等敏感操作必须写审计日志。
- MVP 的 AI 运维是规则化运维助手，不接入大模型。

## 配置

规则：

- 设置页必须接入 `Config` 表。
- 支持保存系统名称、机构名称、数据保留年限、提醒开关、备份时间、备份保留天数、自动备份开关。
- 保存配置必须写审计日志。
